Claude와 함께 이 블로그를 만들면서 웹의 세 가지 기본 기술이 각각 무슨 일을 하는지 또렷하게 알게 되었습니다. 간단히 정리해 둡니다.

## HTML — 뼈대

HTML은 페이지에 **무엇이 있는지**를 정합니다. 제목, 본문, 목록, 링크 같은 구조와 의미를 담당합니다.

- `header`, `main`, `article`, `footer` 같은 시맨틱 태그로 구조를 표현합니다
- `lang="ko"`와 `viewport` 설정이 한글 표시와 모바일 화면의 기본입니다
- 이 블로그의 `index.html`은 빈 틀만 있고, 글 내용은 JavaScript가 채웁니다

## CSS — 겉모습

CSS는 **어떻게 보이는지**를 정합니다. 색, 글꼴, 여백, 배치가 모두 여기서 결정됩니다.

- **CSS 변수**로 색을 모아 두면 다크모드는 변수 값만 바꿔서 해결됩니다
- **미디어쿼리**로 모바일 기준 스타일을 화면이 커질 때 확장합니다
- 본문 폭을 `70ch` 정도로 제한하고 줄 간격을 넉넉히 주면 글이 훨씬 읽기 좋아집니다

```css
:root { --text: #1f2328; }
:root[data-theme="dark"] { --text: #e6e8eb; }

body { color: var(--text); }
```

## JavaScript — 동작

JavaScript는 페이지가 **어떻게 움직이는지**를 정합니다. 이 블로그에서 하는 일은 다음과 같습니다.

1. `fetch`로 글 목록과 마크다운 파일을 불러옵니다
2. 마크다운을 HTML로 변환해 화면에 넣습니다
3. 주소의 `#/post/...` 부분을 읽어 어떤 화면을 보여줄지 정합니다
4. 다크모드 선택을 `localStorage`에 저장합니다

## 한눈에 비교

| 기술 | 역할 | 이 블로그에서 |
| --- | --- | --- |
| HTML | 구조 | 페이지 틀, 헤더, 본문 영역 |
| CSS | 디자인 | 다크모드, 모바일 레이아웃 |
| JavaScript | 동작 | 글 불러오기, 변환, 라우팅 |

> 글을 화면에 넣을 때는 항상 먼저 이스케이프해야 합니다. 편리함보다 보안이 먼저입니다.

## 정리

세 기술은 서로 겹치지 않고 역할이 나뉘어 있어서, 하나를 고쳐도 나머지가 크게 흔들리지 않았습니다. 프레임워크 없이도 이만큼 만들 수 있다는 점이 가장 큰 수확이었습니다.
